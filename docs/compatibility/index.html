Gateway connect

selfhost gateway connect <agent> points an agent at the team's AI gateway with the person's virtual key, and selfhost gateway disconnect puts the files back byte for byte. Only API key traffic goes through a gateway: an agent signed in with a subscription is left as it is unless --api-billing is given. Each version's result is in its gateway-connect check below.

Event schema versions

Every event carries a schema version. The server accepts the current version, and an older one for 12 months after the version that replaced it was released; older events are upgraded on the way in.

Event schemaReleasedAccepted
selfhost.event/v12026-11-07Current

What each check covers

install
The release installs from its npm package or the vendor's download, on Linux x64.
version
The installed CLI runs and reports the version that was installed.
hook-events
Every hook event selfhost installs hooks for is still offered. For Claude Code the list comes from claude doctor; the events it offers that selfhost has no schema for are listed as not modeled.
hook-fields
The payload fields selfhost reads and the answer fields it writes still appear in the CLI.
tool-inputs
Claude Code's own sdk-tools.d.ts still declares the tool input fields the pre-tool check reads.
config
The CLI loads the configuration selfhost policy compile writes for that release: claude doctor for Claude Code settings, codex features list for Codex requirements.toml.
gateway-connect
selfhost gateway connect's settings for this release go into a fresh home, the CLI runs one prompt, and its model request must reach a stand-in gateway on the runner with the virtual key. No API key is used.
suite:*
Fixture sessions and hook payloads through selfhost's schemas, hook mappers, log importers, the selfhost hook command, the policy and context compilers, and gateway connect and disconnect on fixture configs.
live-*
With an API key in CI: a short real session with every hook capturing its payload, checked against the schemas, mapped to ledger events, and the session log imported.

A skipped check could not run in that environment, for example a live session without an API key. Skipped checks never mark a release broken. The same data is in compatibility.json.
